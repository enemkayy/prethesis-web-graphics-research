    Platform Documentation

    Technical documentation for the Pre-thesis Web Graphics Research Platform, outlining platform architecture, independent module specifications, local development setup, and research references.

    1. Project Overview

    The Pre-thesis Web Graphics Research Platform (Graphics Research Hub) is an academic research platform designed to investigate and demonstrate four distinct web graphics technologies. The project explores implementation feasibility, rendering characteristics, user interaction capabilities, and cross-browser/device compatibility within a shared client-side web environment.

    To maintain strict architectural boundaries, each graphical prototype is developed and hosted as an independent document loaded through a shared sandboxed viewport (<iframe>). The common portal coordinates navigation, header metadata, and overview summaries without intruding into internal module rendering loops.

    2. Module Overview

    The research platform encompasses four independent Proof-of-Concept (PoC) modules. Each module addresses a specific graphics domain and technology stack:

    Module 01 Prototype Planned

    WebGL Graphics

    Direct GPU pipeline rendering using native WebGL 2.0 and GLSL ES 3.0 shaders. Focuses on vertex buffer management, transformation matrices, and shader-driven lighting without external 3D libraries.

    • GLSL ES 3.0

    5. Getting Started

    Because modern browsers enforce strict security policies regarding local file access (file:// protocol) for WebGL shaders, WebAssembly binaries, iframe navigation, and ES modules, the platform should be served via a local static HTTP server.

    Why an HTTP server is required: Cross-origin and local file restrictions prevent browsers from loading WebGL shaders, WebAssembly memory files, and iframe documents reliably over file://. Serving via HTTP/HTTPS guarantees identical behavior to GitHub Pages deployment.

    Local Server Commands

    Choose any lightweight static server tool: 

    # Option A: Python 3 built-in HTTP server
python -m http.server 8000

# Option B: Node.js (via npx serve)
npx serve .

# Option C: VS Code Live Server extension
# Right-click "index.html" and select "Open with Live Server"

    Once the server is running, navigate to http://localhost:8000/ (or the assigned port) in any modern desktop browser (Chrome, Firefox, Edge, or Safari).

    About Graphics Research Hub

    The Pre-thesis Web Graphics Research Platform is an academic study investigating browser-based graphics paradigms, architectural boundaries, and device compatibility across four independent Proof-of-Concept prototypes.

    1. Research Purpose & Objectives

    Web browsers have evolved from static document viewers into high-performance execution environments capable of rendering complex 3D scenes, physics simulations, and immersive spatial experiences. However, modern web graphics technologies range widely in abstraction levels—from low-level GPU programming interfaces to heavy game engine runtimes and declarative web components.

    The primary objective of this pre-thesis research is to build a unified comparative evaluation platform to investigate:

    • Implementation Feasibility: Evaluating the development complexity, runtime footprint, and asset requirements of each approach.
    • Interaction Capabilities: Measuring responsive user control, camera navigation, and input handling within the browser.
    • Architectural Isolation: Demonstrating how diverse graphics technologies can coexist under a unified web portal without cross-contamination.
    • Cross-Device Compatibility: Identifying the practical boundaries of WebGL 2.0, mobile Augmented Reality, and WebXR Virtual Reality across desktop and mobile devices.

    2. Four Research Domains

    The platform divides modern browser graphics into four representative domains:

    1. Low-Level Native Graphics Pipeline

    Direct interaction with the GPU through WebGL 2.0 and GLSL ES 3.0 shaders. This domain investigates manual buffer memory allocation, transformation matrix mathematics, and shader compilation pipelines with zero external abstraction overhead.

    2. Engine-Based Graphical Applications

    High-fidelity 3D object inspection leveraging Unity's physically-based rendering (PBR) engine exported to WebAssembly. This domain evaluates orbit camera manipulation, material parameter customization, and engine runtime overhead.

    3. Real-Time Interactive Web Games

    First-person navigation and environmental interaction inside a bounded 3D space. This domain explores keyboard/mouse input capture, collision detection with BoxCollider geometry, and raycast-driven object interaction in a browser game build.

    4. Immersive Web & Spatial Computing

    Declarative 3D model visualization and augmented reality spatial placement using Google <model-viewer>, combined with an empirical study into WebXR Device API feasibility for immersive Virtual Reality headsets.

    3. Academic Scope & Project Boundaries

    Academic Pre-thesis Scope: This platform is developed specifically for academic research and Proof-of-Concept demonstration. It is not intended as a commercial gaming portal, production product configurator, or continuous benchmarking suite.

    In alignment with pre-thesis research boundaries:

    • No Backend Services: The platform operates 100% client-side with zero databases, server-side APIs, or authentication layers.
    • Pure Web Standards: The portal shell uses standard HTML5, CSS3, and Vanilla JavaScript (no React, Vue, Next.js, or build-step dependencies).
    • Independent Contexts: Each module runs in its own document context via an iframe, ensuring that memory leaks or execution errors in one module do not crash the portal or other prototypes.

    4. Technology Summary

    The platform architecture leverages the following foundational technologies:

    • Web Portal: Semantic HTML5, CSS3 Custom Properties (Design Tokens), Vanilla JavaScript (ES6+ Hash Router).
    • Typography: Self-hosted IBM Plex Sans and IBM Plex Mono fonts (WOFF2 format).
    • Target Modules: WebGL 2.0 / GLSL ES 3.0, Unity WebGL (C# / WebAssembly), Google <model-viewer>, WebXR Device API.
    • Hosting & Deployment: GitHub Pages static hosting using strict relative resource paths (./ and ../).

    5. Device & Browser Compatibility Note

    Web graphics and spatial computing APIs depend directly on underlying hardware acceleration, GPU drivers, and browser platform implementations:

    • WebGL 2.0: Supported on modern desktop and mobile browsers (Chrome, Edge, Firefox, Safari 15+). Hardware acceleration must be enabled.
    • Unity Web Builds: Require WebAssembly (Wasm) and WebGL 2.0 support. Memory allocation is bounded by mobile browser memory limits.
    • Augmented Reality (AR): 1:1 real-world spatial placement requires AR-compatible hardware (Google Play Services for AR / ARCore on Android, or ARKit / Quick Look on iOS Safari).
    • Virtual Reality (WebXR): Immersive VR sessions require a compatible WebXR browser (e.g. Meta Quest Browser, Chrome on Android, or desktop browsers with connected VR headsets).

    Documenting these device and browser limitations under standard consumer web conditions is one of the primary academic outcomes of this research project.
